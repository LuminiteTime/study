# Production readiness review

## Код
- [ ] У всех операторов есть `uid` (проверяет `PipelineTopologyTest`)
- [ ] `GENERIC_TYPES=false`, в состоянии нет Kryo
- [ ] Битая запись уходит в DLQ и не валит задание
- [ ] У каждого состояния есть TTL или обоснование его отсутствия
- [ ] Идентификаторы алертов детерминированы

## Устойчивость
- [ ] Интервал чекпоинта выбран осознанно и согласован с задержкой exactly-once
- [ ] `transaction.timeout.ms` больше интервала чекпоинта плюс простоя
- [ ] Чекпоинты лежат во внешнем хранилище, `RETAIN_ON_CANCELLATION`
- [ ] Включена HA, проверено падение JobManager
- [ ] Проверено восстановление из savepoint прошлой версии
- [ ] Проверено отключение каждой внешней системы

## Масштаб
- [ ] `pipeline.max-parallelism` задан заранее и не меняется
- [ ] Посчитан объём состояния и запас памяти
- [ ] Прогнан нагрузочный тест с запасом в два раза

## Наблюдаемость
- [ ] Дашборд показывает лаг, отставание, busy, backpressure, чекпоинты, рестарты
- [ ] Настроены алерты и у каждого есть раздел runbook
- [ ] Лаг измеряется и снаружи задания

## Безопасность
- [ ] Секреты передаются через менеджер секретов, их нет в коде и образе
- [ ] Включены TLS и аутентификация для Kafka и PostgreSQL
- [ ] Web UI и REST закрыты от внешней сети
