Глоссарий урока

Test harness
Набор классов из тестовых jar Flink. Создаёт оператор в макете окружения и даёт вручную подавать записи, двигать время и снимать снимки. Сети и кластера там нет.
Restore-тест
Тест, который снимает снимок состояния с одного экземпляра оператора и поднимает из него другой. Воспроизводит перезапуск задания в памяти.
Тест топологии
Тест, который строит граф задания и проверяет его свойства, ничего не запуская. Так называем его в этом курсе, отдельного термина у Flink нет.
StreamGraph
Граф задания, в котором каждый оператор описан отдельным узлом. Получается из описания задания на клиенте.
JobGraph
Граф, который отправляется на кластер. Цепочки операторов в нём уже объединены в одну вершину.
uid
Постоянный идентификатор оператора, который задаёшь ты. По нему Flink находит состояние оператора в savepoint.
OperatorID
Внутренний идентификатор оператора во Flink. Состояние в снимке хранится под ним.
MiniCluster
Встроенный кластер Flink, работающий в той же JVM, что и тест. В JUnit 5 его поднимает расширение MiniClusterExtension.
E2E, сквозной тест
Тест, который проверяет всю систему вместе с настоящими внешними зависимостями. В PayGuard это Kafka и PostgreSQL в контейнерах.
Testcontainers
Библиотека, которая запускает контейнеры Docker из кода теста и убирает их после него.
JUnit
Основная библиотека модульных тестов в Java. Тег @Tag помечает тесты, чтобы запускать их выборочно.
AssertJ
Библиотека проверок для тестов на Java с цепочками вроде assertThat(x).isEmpty() и подробными сообщениями о падении.
Сериализация
Превращение объекта в байты, чтобы передать его по сети или сохранить. Функции Flink передаются на TaskManager через сериализацию Java, поэтому их поля обязаны быть Serializable.
ClosureCleaner
Класс Flink, который чистит функцию от лишних ссылок и проверяет, что её можно сериализовать. Вызывается при добавлении функции в граф.
Kryo
Библиотека сериализации общего назначения. Flink включает её для типов, которые сам разобрать не может, и считает их чёрным ящиком. Эволюция схемы для таких типов не работает, поэтому в PayGuard Kryo запрещён.
Savepoint
Снимок состояния задания, сделанный по команде. Из него запускают новую версию после обновления.
Чекпоинт (checkpoint)
Снимок состояния задания, который Flink снимает сам по расписанию ради восстановления после падения.
Состояние (state)
Данные, которые оператор хранит между записями и которые входят в снимки.
TTL
Срок жизни записи состояния. По его истечении запись считается удалённой.
Водяной знак (watermark)
Метка в потоке, которая сообщает, до какого момента времени события уже пришли.
RocksDB
Встраиваемая база данных на диске. Хранилище состояния Flink для больших объёмов.
Apache Kafka
Распределённый журнал сообщений. В PayGuard это и источник платежей, и приёмник алертов.
Транзакция Kafka
Группа записей, которая становится видна потребителям с read_committed только после фиксации. Коннектор Flink фиксирует её на чекпоинте.
Exactly-once
Гарантия, при которой каждая запись влияет на результат ровно один раз, в том числе после сбоя.
DLQ (dead letter queue)
Отдельный топик для записей, которые не удалось обработать. Они не роняют задание и остаются доступны для разбора.
PostgreSQL
Реляционная база данных. В PayGuard хранит справочник продавцов и итоги.
Classpath
Упорядоченный список jar и каталогов, где JVM ищет классы. Из одинаковых классов загружается первый найденный.
commons-lang3
Библиотека вспомогательных классов Apache Commons. Её использует Testcontainers.
OpenLineage
Стандарт и библиотеки для сбора данных о происхождении данных. JDBC-коннектор Flink тянет его транзитивно.
Транзитивная зависимость
Библиотека, которая попала в проект потому, что её требует другая зависимость.
BOM (bill of materials)
Файл с согласованными версиями группы библиотек. Подключается в Gradle через platform, и версии отдельных модулей указывать не нужно.
Толстый jar (fat jar)
Один файл с твоим кодом и всеми его зависимостями. Этот jar отправляется на кластер.
GitHub Actions
Сервис CI от GitHub. Запускает задания из файлов в каталоге .github/workflows на каждое указанное событие.
CI (непрерывная интеграция)
Автоматическая сборка и запуск тестов на каждое изменение кода.
Раннер (runner)
Машина, на которой GitHub Actions выполняет задания.
Docker
Программа, которая запускает приложения в изолированных контейнерах из готовых образов.
