Глоссарий урока

CDC (change data capture)
Захват изменений. Изменения строк читаются из журнала базы и идут потоком в другие системы.
PostgreSQL
Реляционная база данных с открытым кодом. В курсе в ней живут справочник продавцов и итоги.
WAL (write-ahead log)
Журнал упреждающей записи PostgreSQL. Изменение попадает в файлы данных только после записи в него.
LSN (log sequence number)
Номер позиции в WAL.
Логическое декодирование (logical decoding)
Механизм PostgreSQL, который превращает WAL в поток изменений строк для внешнего читателя. Требует wal_level = logical.
pgoutput
Стандартный плагин вывода логического декодирования PostgreSQL, на нём работает встроенная логическая репликация.
Слот репликации (replication slot)
Объект на сервере PostgreSQL, который хранит позицию читателя и запрещает удалять журнал после неё. Живёт независимо от подключения.
REPLICA IDENTITY
Настройка таблицы PostgreSQL, которая решает, какие старые значения строки записать в журнал при UPDATE и DELETE.
Debezium
Библиотека чтения журналов баз данных. Flink CDC использует её классы внутри своих источников.
Инкрементальный снимок (incremental snapshot)
Начальное чтение таблицы частями по первичному ключу. Чанки читаются параллельно и без глобальной блокировки на чтение.
Дозаполнение (backfill)
Чтение журнала между нижней и верхней границами чанка, чтобы влить изменения, случившиеся во время запроса.
Changelog
Поток записей с видом изменения, +I вставка, -U и +U старая и новая версии при обновлении, -D удаление. Подробно в уроке 14.
Upsert
Запись, которая вставляет строку или заменяет существующую с тем же ключом.
Tombstone
Сообщение Kafka с ключом и пустым значением. Означает удаление этого ключа.
Компактируемый топик (compacted topic)
Топик Kafka с cleanup.policy=compact. Брокер хранит для каждого ключа как минимум последнее значение.
Apache Kafka
Распределённый журнал сообщений. Записи лежат в топиках и хранятся заданное время.
Топик (topic)
Именованный журнал в Kafka, разбитый на партиции.
Чекпоинт (checkpoint)
Согласованный снимок состояния задания Flink. С него задание продолжает работу после сбоя.
Lakehouse
Таблицы из файлов в дешёвом хранилище с метаданными, которые дают атомарную публикацию изменений. Читать такую таблицу можно разными движками.
Apache Paimon
Формат таблиц для озера данных с упором на потоковую запись и обновления по первичному ключу.
Apache Iceberg
Другой открытый формат таблиц для озера данных. В этом курсе на стенде не используется.
Parquet
Колоночный формат файлов. По умолчанию Paimon хранит в нём данные.
Бакет (bucket)
Группа файлов внутри партиции таблицы Paimon. У каждого бакета таблицы с ключом своё LSM-дерево.
LSM-дерево (log-structured merge-tree)
Способ хранения, при котором записи копятся в памяти, сбрасываются отсортированными файлами и потом сливаются.
Compaction
В Paimon фоновое слияние файлов бакета, которое сокращает работу при чтении.
Снимок таблицы Paimon
Опубликованное состояние таблицы, файл snapshot/snapshot-N со ссылками на схему и манифесты.
Манифест (manifest)
Файл метаданных Paimon, который перечисляет добавленные и убранные файлы данных.
Механизм слияния (merge engine)
Правило Paimon, по которому записи с одним ключом дают одну строку. По умолчанию deduplicate, он оставляет последнюю.
Чтение в прошлое (time travel)
Запрос к одной из сохранённых старых версий таблицы.
Apache Hadoop
Платформа распределённого хранения и вычислений. Paimon обращается к её классам, поэтому нужен jar даже при работе с локальным диском.
At-least-once
Гарантия доставки, при которой запись не теряется, но может прийти повторно.
