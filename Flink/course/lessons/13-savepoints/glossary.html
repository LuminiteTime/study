Глоссарий урока

Savepoint
Снимок состояния задания, который создаёшь ты, командой или через REST. Flink его не удаляет. Нужен для смены кода, параллелизма, версии Flink и бэкенда состояния.
Чекпоинт (checkpoint)
Снимок, который Flink снимает сам по интервалу и удаляет, когда он больше не нужен. Предназначен для восстановления после сбоя.
Формат canonical
Формат savepoint, единый для всех бэкендов состояния. Выбирается по умолчанию, позволяет сменить бэкенд и лучше всего переживает эволюцию схемы.
Формат native
Формат savepoint, родной для бэкенда, у RocksDB это SST-файлы. Быстрее создаётся и восстанавливается, но не позволяет сменить бэкенд.
uid
Постоянный идентификатор оператора, заданный в коде. Из него хешем получается OperatorID, по которому состояние в снимке находит оператор.
OperatorID
16-байтовый идентификатор оператора внутри Flink. Получается хешем murmur3 от uid или выводится из положения оператора в графе.
stop
Команда CLI, которая снимает savepoint и после его успеха завершает источники. Задание переходит в FINISHED.
cancel
Команда CLI, которая останавливает задание сразу, без savepoint.
--allowNonRestoredState
Флаг запуска, который разрешает выбросить состояние операторов, отсутствующих в новой программе. Короткая форма -n.
--drain и MAX_WATERMARK
Флаг команды stop, который перед последним барьером отправляет максимальный watermark. Срабатывают все таймеры по времени события. Подходит только для окончательной остановки.
Эволюция схемы (schema evolution)
Изменение типа состояния между версиями программы с сохранением данных. Для POJO и Avro Flink мигрирует состояние сам.
Снимок сериализатора (serializer snapshot)
Описание формата, в котором записано состояние. Лежит в снимке рядом с данными. По нему новый сериализатор решает, совместим ли он со старыми байтами.
POJO
Обычный Java-класс, который Flink разбирает на поля и сериализует сам. Record во Flink 2.2 обрабатывается как POJO.
Record
Неизменяемый класс Java с компонентами в заголовке. Компилятор сам создаёт конструктор, геттеры, equals и hashCode.
Kryo
Универсальная библиотека сериализации, которой Flink пользуется для незнакомых типов. Не поддерживает эволюцию схемы. В PayGuard запрещена настройкой pipeline.generic-types: false.
Группа ключей (key group)
Единица разбиения ключей и состояния. Номер группы зависит только от ключа и числа групп, поэтому при смене параллелизма состояние переносится целыми группами.
Максимальный параллелизм (maxParallelism)
Число групп ключей оператора и верхняя граница его параллелизма. Записано в снимке. Автоматически вычисленное значение уступает числу из снимка, заданное явно должно с ним совпадать.
Rescale
Запуск задания из снимка с другим параллелизмом. Состояние с ключом раздаётся новыми диапазонами групп, состояние без ключа по кругу.
Состояние без ключа (operator state)
Состояние, привязанное к подзадаче оператора, например список партиций источника. При rescale раздаётся по кругу.
State Processor API
Библиотека Flink для чтения, записи и правки снимков пакетной программой. Подключается артефактом flink-state-processor-api.
Режим BATCH
Режим выполнения для конечных данных. Программа завершается, когда вход прочитан. State Processor API работает только в нём.
CloseableIterator
Итератор Flink, который нужно закрыть после использования. Его возвращает executeAndCollect(), закрытие освобождает ресурсы кластера.
RocksDB
Встраиваемое хранилище ключ-значение на диске. Бэкенд состояния PayGuard с урока 11.
Apache Kafka
Распределённый журнал сообщений. Смещения чтения источника хранятся в снимке, поэтому новая версия задания продолжает с того же места.
Slot sharing
Размещение подзадач разных операторов в одном слоте. Благодаря ему задание с параллелизмом 4 помещается в 4 слота.
