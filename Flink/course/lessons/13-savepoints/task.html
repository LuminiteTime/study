Задание. Инспектор состояния

Дежурному нужно знать, какие карты самые активные, и он не хочет ради этого трогать запущенное задание. Напиши класс dev.study.payguard.job.StateInspector, который читает savepoint через State Processor API.

  1. Добавь в build.gradle.kts зависимость org.apache.flink:flink-state-processor-api той же версии, что Flink. Подумай, в какую конфигурацию её положить. В дистрибутиве Flink этот jar лежит в opt/, в lib/ его нет.
  2. Путь к снимку принимай аргументом --savepoint.
  3. Прочитай состояние с ключом оператора card-profile и собери пары «карта и профиль».
  4. Напечатай общее число карт в состоянии и пять карт с наибольшим числом платежей.
  5. Запусти инспектор на кластере через flink run с флагом -c на снимке второй версии. Учти, что инспектор тоже задание и ему нужен свободный слот.

Готово, если команда завершается без исключений и печатает строку с числом карт и пять строк топа, отсортированных по убыванию paymentCount.

Подсказки. Строки uid и имя состояния уже вынесены в CardProfileFunction, бери их оттуда. State Processor API работает только в режиме BATCH. Дескриптор состояния в читателе должен совпадать с дескриптором в функции по имени и классу. У DataStream есть несколько способов забрать результат в клиент, и один из них ведёт себя неожиданно при большом лимите. Прочитай его код до того, как выбирать.
