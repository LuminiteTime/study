Правило в конце monitoring/alerts.yml.

Выражение читается изнутри наружу. Ряды records_lag_max отбираются по заданию и оператору источника платежей. max by (subtask_index) оставляет по одному ряду на подзадачу и отбрасывает остальные метки, например tm_id и task_attempt_id, которые меняются после перезапуска. sum складывает подзадачи в одно число. Порог 5000 при 200 платежах в секунду означает примерно 25 секунд отставания. for: 2m не даёт алерту загораться, пока задание догоняет топик после короткого рестарта. Выражение многострочное, поэтому записано блоком YAML через |. В аннотации {{ $value }} подставляет значение выражения в момент срабатывания.

Панель в payguard.json стоит второй в списке.

Запрос тот же, что в правиле, без порога. Единица short подписывает ось числами с сокращениями вроде 11K.

Как проверить.

docker compose restart prometheus grafana
curl -s localhost:9090/api/v1/rules | jq -r '.data.groups[].rules[].name'
docker compose stop taskmanager
sleep 100
docker compose start taskmanager
sleep 60
curl -s localhost:9090/api/v1/alerts | jq -r '.data.alerts[] | "\(.labels.alertname) \(.state)"'

Первый запрос должен перечислить шесть правил. На нашем стенде через 60 секунд после возврата TaskManager лаг был 11220 записей, и PayGuardKafkaLagHigh стоял в pending. Пока TaskManager остановлен, это правило молчит, и это ожидаемо, за этот промежуток отвечает PayGuardSourceSilent.

В исходниках

records-lag-max это метрика клиента Kafka, максимальный лаг среди партиций, которые читает консьюмер. Подзадача у нас читает две партиции из четырёх, и сумма максимумов по подзадачам может быть меньше полного лага. Для порога «отстали сильно» этой точности хватает. У коннектора есть и точная сумма, метрика pendingRecords, которая складывает records-lag всех партиций подзадачи.

В Prometheus она называется flink_taskmanager_job_task_operator_pendingRecords. На стенде мы её не проверяли, правило в снапшоте написано на records_lag_max. Если перейдёшь на pendingRecords, запроси её сначала через API и сравни с лагом группы потребителей от kafka-consumer-groups.sh.
