Ответ

В новом файле настройки сгруппированы вложенным YAML, как в родном config.yaml. Из памяти оставлен один ключ process.size, остальные области Flink вычислит сам. Ключи bind-host и rest.bind-address обязательны, потому что без них процесс слушает только localhost и TaskManager из соседнего контейнера до него не достучится.

Запуск из корня проекта. Псевдоним jobmanager нужен, чтобы TaskManager нашёл его по адресу из конфига.

docker network create l1net
docker run -d --name l1jm --network l1net --network-alias jobmanager -p 18081:8081 \
  -v "$PWD/conf/config.yaml:/opt/flink/conf/config.yaml:ro" flink:2.2.1-java17 jobmanager
docker run -d --name l1tm --network l1net \
  -v "$PWD/conf/config.yaml:/opt/flink/conf/config.yaml:ro" flink:2.2.1-java17 taskmanager

curl -s localhost:18081/overview | jq -c '{tm: .taskmanagers, slots: .["slots-total"], version: .["flink-version"]}'
curl -s localhost:18081/jobmanager/config \
  | jq -c '[.[] | select(.key | test("state.backend.type|numberOfTaskSlots|checkpointing.dir|parallelism.default"))]'
{"tm":1,"slots":4,"version":"2.2.1"}
[{"key":"parallelism.default","value":"2"},{"key":"taskmanager.numberOfTaskSlots","value":"4"},{"key":"execution.checkpointing.dir","value":"file:///tmp/flink-checkpoints"},{"key":"state.backend.type","value":"hashmap"}]

В логе JobManager появится строка config-parser-utils.sh: line 42: /opt/flink/conf/config.yaml: Read-only file system. Скрипт запуска пытается дописать файл, а смонтирован он только для чтения. На работу это не влияет, но переменная FLINK_PROPERTIES при таком монтировании не применится.

Убери за собой командами docker rm -f l1jm l1tm и docker network rm l1net. В проекте мы продолжим использовать FLINK_PROPERTIES, потому что все настройки видны в одном файле Compose.
