Что будет в конце

На твоей машине работают Kafka и кластер Flink из одного JobManager и одного TaskManager. Генератор пишет платежи в топик, а задание печатает их в лог. Это скелет, на котором будет расти весь проект.

Шаг 1. Создай проект

Создай папку payguard рядом со своим Makefile, а внутри два файла. Первый задаёт имя проекта. Gradle ставить не обязательно, wrapper можно скопировать из solutions/lesson-01, это папка gradle/ и файлы gradlew и gradlew.bat. Wrapper сам скачает Gradle 9.8.1 при первом запуске.

Второй файл описывает сборку и зависимости.

Разберём места, где сборка Flink-задания отличается от обычного Java-приложения. Самое важное здесь разделение зависимостей.

ПРОСТЫМИ СЛОВАМИ

Создаём свою группу зависимостей flinkProvided. Классы Flink уже лежат в образе, и если положить их в jar второй раз, начнутся конфликты загрузчиков классов.

Эти классы нужны при компиляции и в тестах, поэтому compileOnly и testImplementation наследуют группу.

flink-streaming-java это DataStream API, flink-clients умеет запускать задание, flink-connector-base содержит общую основу коннекторов.

Коннектор Kafka в образе отсутствует, поэтому он идёт через implementation и попадает в jar. Его версия 5.0.0-2.2 читается как версия коннектора плюс версия Flink, под которую он собран.

Jackson нужен для JSON в генераторе и позже в задании.

Реализация логгера нужна только генератору на твоей машине. В кластере логгер уже есть.

Блок tasks.shadowJar собирает толстый jar, в котором лежит твой код и все зависимости из implementation. Строка с Main-Class нужна, чтобы flink run нашёл точку входа без лишних аргументов. Вызовы mergeServiceFiles и filesMatching склеивают файлы META-INF/services из разных библиотек. Без них коннектор теряет регистрацию своих компонентов. Исключение подписей *.SF нужно потому, что подпись чужого jar становится недействительной после пересборки.

Шаг 2. Опиши стенд в Docker Compose

Положи в корень проекта docker-compose.yml.

Настройки Flink переданы переменной FLINK_PROPERTIES. Скрипт запуска образа дописывает её содержимое в родной config.yaml, поэтому ключи здесь проверенные и файл монтировать не нужно. Папка build/libs смонтирована в контейнер как /jobs, так собранный jar виден JobManager. У Kafka два слушателя. Контейнеры ходят на kafka:9092, а твоя машина на localhost:9094. Служба kafka-init создаёт топики с четырьмя партициями и завершается.

Шаг 3. Модель и генератор платежей

Платёж описан неизменяемым record. Сумма хранится в минимальных единицах валюты в long, чтобы не ловить ошибки округления double.

Генератор создаёт нагрузку, близкую к настоящей. Треть платежей идёт в одного продавца m-0000, часть приходит с опозданием, часть дублируется, часть битая. Эта грязь понадобится нам в следующих уроках.

Шаг 4. Первое задание

Создай src/main/java/dev/study/payguard/job/PayGuardJob.java.

ПРОСТЫМИ СЛОВАМИ

Получаем окружение. При запуске через flink run оно подключено к кластеру. Как и SparkSession, оно служит точкой входа, но ничего не исполняет сразу.

Описываем источник Kafka. setGroupId задаёт группу потребителей, latest велит читать только новые записи, а SimpleStringSchema превращает байты в строку.

fromSource добавляет источник в граф. Про noWatermarks поговорим в уроке 5, пока время события нам не нужно. Третий аргумент это имя в интерфейсе.

print добавляет приёмник, который пишет записи в стандартный вывод TaskManager. В терминале клиента этих строк не будет.

До этой строки был только план. env.execute отправляет его на кластер, похоже на действие start() в Spark.

Шаг 5. Собери и запусти

На macOS сначала укажи JDK 17, если по умолчанию у тебя другая версия. Порядок команд здесь не случайный. Если поднять Compose раньше сборки, Docker смонтирует пустую папку build/libs, и jar в контейнере не появится.

export JAVA_HOME=$(/usr/libexec/java_home -v 17)
./gradlew shadowJar
docker compose up -d --wait

Флаг --wait заставляет команду дождаться готовности контейнеров. Теперь спроси у кластера, как он себя чувствует. REST-интерфейс отвечает на порту 8081, там же открывается Web UI.

curl -s localhost:8081/overview | jq .
{
  "taskmanagers": 1,
  "slots-total": 4,
  "slots-available": 4,
  "jobs-running": 0,
  "jobs-finished": 0,
  "jobs-cancelled": 0,
  "jobs-failed": 0,
  "flink-version": "2.2.1",
  "flink-commit": "450c63e"
}

Поля taskmanagers и slots-total сразу показывают то, чего не было при твоём запуске через Makefile. Отправь задание и запусти генератор на пять платежей в секунду.

docker compose exec jobmanager flink run --detached /jobs/payguard-1.0.0.jar
./gradlew loadgen --args="--rate 5 --dup 0.02 --bad 0.01"

Флаг --detached отдаёт терминал сразу после отправки и оставляет задание работать. Вывод print живёт в логе TaskManager, смотри его из второго терминала.
