Глоссарий урока

Total Process Memory
Вся память процесса TaskManager, ключ taskmanager.memory.process.size. В контейнере равна его лимиту.
Total Flink Memory
Память процесса без JVM Metaspace и JVM Overhead. Из неё выделяются кучи, off-heap, сетевая и managed memory.
Managed memory
Нативная память вне кучи, которую распределяет сам Flink. В потоковых заданиях её получает RocksDB или ForSt, по умолчанию 0,4 от Total Flink Memory.
Task Heap
Куча JVM для операторов и пользовательского кода. Получает остаток Total Flink Memory после всех остальных областей.
Память фреймворка (framework memory)
Куча и off-heap память под внутренние нужды TaskManager, по 128 МиБ. В слоты не раздаётся.
Сетевая память (network memory)
Direct-память под сетевые буферы между подзадачами. Доля 0,1 от Total Flink Memory, не меньше 64 МиБ.
JVM Overhead
Запас нативной памяти под стеки потоков, кэш JIT и внутренние структуры JVM. Доля 0,1 от процесса в границах 192 МиБ и 1 ГиБ.
JVM Metaspace
Область JVM под метаданные загруженных классов, по умолчанию 256 МиБ, ограничена флагом -XX:MaxMetaspaceSize.
Off-heap и direct-память
Память вне кучи JVM. Direct-буферы Java ограничены флагом -XX:MaxDirectMemorySize, прочая нативная память ничем внутри JVM не ограничена.
OOMKilled
Статус контейнера Kubernetes, который убило ядро Linux за превышение лимита памяти. Исключения в JVM при этом не возникает.
Kubernetes
Система запуска контейнеров на кластере машин. Каждому контейнеру задаётся лимит памяти. Подробно в уроке 20.
RocksDB
Встраиваемое хранилище ключей и значений на диске, устроенное как LSM-дерево. Во Flink служит бэкендом состояния для больших объёмов.
LSM-дерево (log-structured merge tree)
Устройство хранилища, где записи копятся в памяти и сбрасываются на диск неизменяемыми файлами, а фоновые слияния поддерживают порядок.
Memtable
Отсортированная таблица RocksDB в памяти, куда попадают свежие записи. Заполненная memtable сбрасывается на диск SST-файлом.
SST-файл (Sorted String Table)
Неизменяемый файл RocksDB с отсортированными парами ключ и значение.
Компакция (compaction)
Фоновое слияние SST-файлов RocksDB. Убирает перезаписанные версии и удалённые ключи, на этом шаге работает очистка по TTL.
Блочный кэш (block cache)
Кэш RocksDB в памяти для блоков данных, индексов и фильтров из SST-файлов. Во Flink общий для всех состояний слота.
Менеджер буферов записи (write buffer manager)
Компонент RocksDB, ограничивающий общую память всех memtable. Во Flink учитывает её в блочном кэше слота.
Фильтр Блума (Bloom filter)
Компактная структура, которая быстро отвечает, что ключа в файле точно нет. Позволяет RocksDB не читать лишние SST-файлы.
Семейство колонок (column family)
Отдельное пространство ключей внутри RocksDB со своими memtable. Во Flink каждое состояние оператора это своё семейство колонок.
ForSt
Бэкенд состояния Flink 2.x, устроенный почти так же, как RocksDB. Умеет держать SST-файлы во внешнем хранилище и работает с асинхронным доступом. Экспериментальный.
Разделённое хранение состояния (disaggregated state)
Режим Flink 2.x, в котором основная копия состояния лежит во внешнем хранилище вроде S3, а локальный диск служит кэшем.
State V2
Новый API состояния Flink 2.x с асинхронными методами, которые возвращают StateFuture. Включается вызовом enableAsyncState().
StateFuture
Результат асинхронного обращения к состоянию. Продолжение обработки задаётся методами thenAccept, thenApply, thenCompose.
Capacity planning
Расчёт ресурсов задания заранее, по размеру состояния, скорости потока и запасу на восстановление.
Prometheus
Система сбора метрик. Периодически опрашивает процессы Flink и хранит временные ряды, подробно в уроке 17.
Память экзекутора Spark
spark.executor.memory задаёт кучу экзекутора, spark.executor.memoryOverhead память вне кучи. Вместе они дают размер контейнера.
