Ответ

Скрипт делает три запроса. Цикл идёт только по запущенным заданиям, поэтому завершённые не засоряют вывод.

ПРОСТЫМИ СЛОВАМИ

set -euo pipefail останавливает скрипт при первой ошибке.

${FLINK_REST:-http://localhost:8081} берёт адрес из переменной окружения, а без неё подставляет значение по умолчанию.

Первый запрос читает /overview. Занятые слоты вычисляются как разность slots-total и slots-available. Дефис в имени поля заставляет писать .["slots-total"].

Цикл берёт идентификаторы из /jobs. Там статус лежит в поле status, и нам нужны только значения RUNNING.

Для каждого задания запрашиваем /jobs/$job_id. Здесь статус лежит уже в поле state, а идентификатор в поле jid. Запятая в jq выдаёт сначала строку заголовка, потом по строке на вершину.

Статус вершины в выводе нужен потому, что статус задания RUNNING ставится раньше, чем появляются слоты. Об этом мы говорили в теории.

Проверь работу двумя запусками, с заданием и без него. Заодно убедись, что переменная работает, задав неверный адрес.

chmod +x scripts/cluster-status.sh
./scripts/cluster-status.sh
FLINK_REST=http://localhost:9999 ./scripts/cluster-status.sh; echo "код выхода $?"

При работающем задании скрипт покажет один TaskManager, два занятых слота из четырёх и единственную вершину с именем из трёх операторов. Без задания останется первая строка. С неверным адресом curl -s вернёт ненулевой код, и pipefail завершит скрипт с этим кодом.
