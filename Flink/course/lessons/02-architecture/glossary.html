Глоссарий урока

Клиент (client)
Программа, которая готовит задание и отправляет его на кластер. Это JVM команды flink run или твоего Java-приложения. В исполнение задания не входит.
JobManager
Процесс, который управляет кластером. Содержит Dispatcher, ResourceManager и по одному JobMaster на задание.
Dispatcher
Компонент JobManager. Даёт REST-интерфейс для отправки заданий, запускает для каждого новый JobMaster и обслуживает Web UI.
ResourceManager
Компонент JobManager, который ведёт учёт слотов кластера и раздаёт их заданиям. На Kubernetes и YARN также запрашивает новые TaskManager.
JobMaster
Компонент JobManager, отвечающий за одно задание. Держит его ExecutionGraph, просит слоты, развёртывает подзадачи, реагирует на сбои.
TaskManager
Рабочий процесс JVM. Выполняет подзадачи в отдельных потоках и обменивается данными с другими TaskManager.
Слот (task slot)
Единица планирования ресурсов в TaskManager. Делит управляемую память поровну и не изолирует CPU. Число задаёт ключ taskmanager.numberOfTaskSlots.
Slot sharing
Размещение подзадач разных вершин одного задания в одном слоте. Включено по умолчанию. Задаётся через группу, по умолчанию она называется default.
Подзадача (subtask)
Один параллельный экземпляр вершины задания. Выполняется в своём потоке на TaskManager.
Параллелизм (parallelism)
Число подзадач вершины. Задаётся в коде, флагом -p или ключом parallelism.default.
StreamGraph
Логический граф программы, где каждый оператор отдельный узел. Создаётся при вызове env.execute. Клиент во Flink 2.2 отправляет на кластер именно его.
JobGraph и JobVertex
Граф, в котором операторы склеены в цепочки. Каждая цепочка это одна вершина (JobVertex). Строится из StreamGraph классом StreamingJobGraphGenerator.
ExecutionGraph
Параллельная версия JobGraph, которую держит JobMaster. На каждую вершину в нём столько элементов, сколько задано параллелизмом.
Цепочка операторов (operator chain)
Операторы, которые работают в одном потоке и передают записи вызовом метода, без сети. Разрывается при keyBy, разном параллелизме или разных группах slot sharing.
FORWARD
Способ передачи, при котором подзадача отправляет записи подзадаче следующего оператора с тем же номером. Без него операторы не склеиваются.
Режим Session
Кластер работает независимо от заданий и обслуживает несколько сразу. main выполняется в клиенте.
Режим Application
Кластер создаётся на одно приложение, а main выполняется в JobManager. Jar уже лежит на classpath кластера.
Режим per-job
Прежний режим развёртывания, удалённый во Flink 2.0. Вместо него используется Application.
Standalone
Способ запуска кластера без системы управления ресурсами. Процессы поднимаешь сам, как у нас в Docker Compose, и новых TaskManager кластер запросить не может.
uid
Постоянный идентификатор оператора, заданный вручную. По нему Flink находит состояние оператора при восстановлении из savepoint.
Savepoint
Снимок состояния задания, который ты создаёшь вручную, чтобы остановить задание и продолжить его с того же места. Разбирается в уроке 13.
Стратегия перезапуска (restart strategy)
Правило, по которому Flink решает, перезапускать ли задание после сбоя и с какой задержкой.
Чекпоинт (checkpoint)
Согласованный снимок состояния, который Flink снимает автоматически. Подробно в уроке 11.
NoResourceAvailableException
Исключение, которым кончается запрос слотов, если кластер не может их дать.
REST-интерфейс
HTTP-интерфейс Dispatcher на порту 8081. Через него работают Web UI, клиент flink и твои скрипты.
Web UI
Панель Flink в браузере. Показывает вершины, подзадачи, слоты и исключения.
jq
Консольная утилита для разбора и преобразования JSON.
Driver (Spark)
Процесс Spark, который выполняет main и планирует работу приложения.
Executor (Spark)
Рабочий процесс Spark, который выполняет задачи. Похож на TaskManager.
Kubernetes
Система управления контейнерами. Flink на ней может сам запрашивать новые TaskManager. Разбирается в уроке 20.
YARN
Менеджер ресурсов из экосистемы Hadoop, на котором тоже можно запускать Flink.
Apache Kafka
Распределённый журнал сообщений. Из него наше задание читает платежи.
