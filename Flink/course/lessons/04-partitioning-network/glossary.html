Глоссарий урока

keyBy
Вызов DataStream API, который разбивает поток по ключу. Все записи с одним ключом попадают в одну подзадачу следующего оператора.
Группа ключей (key group)
Единица разбиения ключей и состояния. Номер группы равен murmurHash от hashCode ключа по модулю maxParallelism. При смене параллелизма группы переходят между подзадачами целиком.
Максимальный параллелизм (maxParallelism)
Число групп ключей оператора и верхняя граница его параллелизма. Без явной настройки вычисляется из параллелизма, минимум 128. После первого запуска не меняется без потери состояния.
MurmurHash
Быстрая хеш-функция, которая перемешивает биты числа. Flink применяет её к hashCode ключа, чтобы похожие ключи расходились по разным группам.
Стратегия распределения (partitioner)
Правило на ребре графа, которое выбирает подзадачу-получателя для каждой записи. Имя стратегии Web UI пишет на ребре, например HASH или REBALANCE.
rebalance
Стратегия, которая раздаёт записи по кругу всем подзадачам получателя. Выравнивает нагрузку, но теряет связь с ключом.
rescale
Стратегия, которая раздаёт записи по кругу только своему подмножеству получателей. Связей меньше, чем у rebalance, и часть передач остаётся локальной.
forward
Стратегия, при которой подзадача отправляет записи подзадаче с тем же номером. Единственная, которая позволяет склеить операторы в цепочку.
broadcast
Стратегия, которая отправляет каждую запись всем подзадачам получателя.
Цепочка операторов (operator chain)
Несколько операторов, склеенных в одну задачу. Запись передаётся между ними вызовом метода, без сериализации и сети.
ResultPartition
Выходные данные одной подзадачи-отправителя. Разбита на подчасти, по одной на каждую подзадачу получателя.
Подчасть (subpartition)
Очередь буферов внутри ResultPartition, предназначенная одной подзадаче получателя.
InputGate
Входной шлюз подзадачи-получателя. Собирает данные со всех отправителей, у каждого отправителя свой канал.
InputChannel
Канал внутри InputGate, который читает одну подчасть одного отправителя. Локальный читает её в памяти того же TaskManager, удалённый получает буферы по сети.
Сетевой буфер (network buffer)
Участок памяти, по умолчанию 32 КиБ, в котором записи едут между подзадачами. Уходит заполненным или по таймауту.
Кредит (credit)
Число свободных буферов, о котором получатель сообщил отправителю. Отправитель шлёт буфер с данными, только если кредит больше нуля.
Эксклюзивный буфер (exclusive buffer)
Буфер, закреплённый за одним удалённым каналом. Во Flink 2.2.1 их 2 на канал.
Плавающий буфер (floating buffer)
Буфер из общего запаса входного шлюза, который канал берёт, когда у отправителя накопилась очередь. Во Flink 2.2.1 их 8 на шлюз.
Backlog
Число буферов, которые ждут отправки в подчасти. Передаётся вместе с каждым буфером, чтобы получатель заранее запросил место.
Обратное давление (backpressure)
Состояние подзадачи, которая не может отправить данные, потому что получатель не выдаёт кредит. Поднимается вверх по графу до источника и проявляется ростом лага.
Перекос ключей (data skew)
Неравная нагрузка подзадач после keyBy. Чаще всего возникает из-за горячего ключа, на который приходится большая доля записей.
Соль (salting)
Приём против перекоса. К горячему ключу дописывают случайный суффикс, считают частичные итоги, а потом сливают их во второй фазе.
busyTimeMsPerSecond и соседи
Метрики подзадачи. Показывают, сколько миллисекунд в секунду она работала, ждала вход и стояла из-за backpressure. В сумме около 1000.
Netty
Java-библиотека для сетевых приложений. Flink передаёт через неё буферы между TaskManager.
Shuffle
Перераспределение данных между параллельными задачами по ключу. В Spark пишет промежуточные файлы на диск между стадиями, в потоковом Flink идёт конвейером через сетевые буферы.
reduce
Агрегация на KeyedStream, которая складывает новую запись с предыдущим результатом того же ключа и выдаёт итог на каждой записи.
