Глоссарий урока

Обогащение (enrichment)
Добавление к записи потока данных из внешнего источника, например уровня риска продавца из базы.
Async I/O
Механизм Flink для запросов во внешние системы без остановки подзадачи. Подзадача отправляет много запросов сразу и выдаёт результаты по мере ответов.
AsyncFunction
Интерфейс функции асинхронного оператора. Метод asyncInvoke запускает запрос и сразу возвращается, метод timeout решает, что делать с зависшим запросом. RichAsyncFunction добавляет open, close и доступ к метрикам.
ResultFuture
Объект, через который асинхронная функция сообщает Flink результат записи. Вызов complete отдаёт результат, completeExceptionally роняет подзадачу.
Capacity
Наибольшее число записей в очереди асинхронного оператора. Когда очередь полна, оператор перестаёт брать записи со входа и включается backpressure.
Timeout
Предельное время на запрос асинхронного оператора, отсчитывается от постановки записи в очередь. По умолчанию истечение перезапускает задание.
Режимы ordered и unordered
Порядок выдачи результатов асинхронного оператора. Ordered выдаёт в порядке входа, unordered по мере готовности, но не через границу watermark.
Head-of-line blocking
Ситуация, когда медленный первый элемент очереди задерживает всех за ним, хотя их работа уже сделана.
Mailbox
Очередь дел потока подзадачи Flink. Обработка записей, таймеры и результаты асинхронных запросов выполняются через неё в одном потоке.
Backpressure
Обратное давление. Медленный оператор перестаёт принимать данные, буферы перед ним заполняются, и замедление доходит до источника.
Состояние оператора (operator state)
Состояние, привязанное к подзадаче, без ключа. В нём асинхронный оператор хранит записи своей очереди для чекпоинта.
Keyed state
Состояние, которое Flink хранит отдельно для каждого ключа. В нём interval join держит буферы обеих сторон.
Interval join
Соединение двух потоков с ключом, при котором запись правого потока должна попасть во временной интервал вокруг записи левого. Работает во времени события и выдаёт только совпавшие пары.
Inner join
Соединение, которое выдаёт только пары с совпадением. Записи без пары не выдаются вовсе.
ProcessJoinFunction
Функция, которую interval join вызывает на каждую найденную пару. Через контекст видны временные метки обеих записей.
KeyedCoProcessFunction
Функция с двумя входами, разбитыми по одному ключу. Даёт keyed state и таймеры, на ней пишут соединения с любой логикой.
Watermark
Отметка времени события в потоке, после которой более ранних событий оператор не ждёт. У оператора с двумя входами равна минимуму по входам.
Таймер (timer)
Отложенный вызов функции, привязанный к ключу. Таймер по времени события срабатывает, когда watermark дошёл до заданного момента.
Кэш (cache)
Копия данных рядом с кодом, чтобы не ходить за ними каждый раз. Здесь это словарь в памяти подзадачи со сроком жизни записей.
Идемпотентность
Свойство операции, при котором повтор не меняет результат. Повторное чтение идемпотентно, повторная отправка SMS нет.
PostgreSQL
Реляционная база данных с открытым кодом. В PayGuard хранит справочник продавцов.
JDBC
Стандартный интерфейс Java для работы с реляционными базами. Его вызовы блокируют поток до ответа базы.
HikariCP
Библиотека пула соединений для JDBC. Держит открытые соединения с базой и выдаёт их потокам по запросу.
CompletableFuture
Класс Java для результата, который появится позже. supplyAsync запускает работу в заданном пуле потоков, whenComplete выполняет код по её окончании.
Пул потоков (ExecutorService)
Набор рабочих потоков Java, которые по очереди выполняют переданные задачи. В AlertEnrichment он выполняет блокирующие запросы к базе.
Healthcheck
Команда в Docker Compose, по которой Docker решает, готов ли контейнер. Флаг --wait ждёт её успеха.
Spark Structured Streaming
Потоковый движок Spark. Соединение двух потоков в нём держит обе стороны в хранилище состояния и чистит его по watermark и условию на время.
