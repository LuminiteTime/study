Глоссарий урока

Обратное давление (backpressure)
Состояние, при котором подзадача не может отдать данные дальше, потому что у неё нет свободного выходного буфера. Распространяется вверх по графу до источника.
Узкое место (bottleneck)
Первая вершина по ходу потока, которая занята почти всю секунду и сама никого не ждёт. Ограничивает пропускную способность всего задания.
busyTimeMsPerSecond
Метрика подзадачи. Миллисекунды из секунды, когда подзадача не ждала ни входа, ни выхода. Вычисляется как остаток, поэтому включает сон и синхронные вызовы внутри функции.
backPressuredTimeMsPerSecond
Метрика подзадачи. Миллисекунды из секунды, когда подзадача ждала свободный буфер на выходе.
idleTimeMsPerSecond
Метрика подзадачи. Миллисекунды из секунды, когда подзадаче нечего было обрабатывать.
Вершина (job vertex)
Узел графа задания в Web UI. Это один оператор или цепочка операторов, сцепленных в одну задачу.
Flame graph
Картинка из многократно снятых стеков вызовов. Ширина полосы метода пропорциональна числу снимков, где он встретился.
On-CPU и Off-CPU
Типы flame graph во Flink. On-CPU берёт потоки в состоянии RUNNABLE, Off-CPU берёт ждущие и заблокированные, Mixed берёт все.
Buffer debloating
Механизм, который подстраивает размер сетевых буферов под измеренную пропускную способность, чтобы данные в полёте разбирались за целевое время. Включается ключом taskmanager.network.memory.buffer-debloat.enabled.
Данные в полёте (in-flight data)
Записи, которые лежат в сетевых буферах между подзадачами и ещё не обработаны получателем.
Unaligned-чекпоинт
Чекпоинт, при котором барьер обгоняет данные в буферах, а обогнанные данные сохраняются вместе со снимком. Подробно в уроке 11.
Таймаут выравнивания
Ключ execution.checkpointing.aligned-checkpoint-timeout. Чекпоинт начинается выровненным и переключается в unaligned, если выравнивание длится дольше.
Повторное использование объектов (object reuse)
Ключ pipeline.object-reuse. Убирает копирование записи между операторами цепочки. Опасен для кода, который хранит или меняет входные объекты.
Сериализация
Превращение объекта в байты и обратно. Во Flink нужна для сети, для состояния в RocksDB и для копий внутри цепочки.
Kryo
Универсальная библиотека сериализации, которую Flink берёт для типов, не распознанных его системой типов. Медленнее родных сериализаторов, в PayGuard запрещена с урока 3.
Перекос данных (data skew)
Неравномерная раскладка записей по подзадачам, обычно из-за ключа, который встречается намного чаще других.
Горячий ключ
Значение ключа с непропорционально большой долей потока. В PayGuard это продавец m-0000 с 30 % платежей.
Соль (salting)
Добавка к ключу, которая разбивает один горячий ключ на несколько. После частичной агрегации соль убирают.
Двухфазная агрегация (local-global)
Агрегация в два шага. Сначала частичные итоги по частям ключа, потом их сложение по настоящему ключу. Во Flink SQL встроена как LocalWindowAggregate и GlobalWindowAggregate.
Лаг Kafka (consumer lag)
Разница между последним смещением в партиции Kafka и смещением, до которого дочитал потребитель. Растёт, если задание не успевает.
RocksDB
Встраиваемое хранилище ключ-значение на диске. Один из бэкендов состояния Flink, каждое обращение к нему проходит через сериализацию.
Spark UI и maxOffsetsPerTrigger
Веб-интерфейс Spark со стадиями и задачами и опция источника Kafka в Structured Streaming, которая ограничивает число смещений на один micro-batch.
