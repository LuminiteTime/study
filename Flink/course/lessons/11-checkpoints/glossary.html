Глоссарий урока

Чекпоинт (checkpoint)
Согласованный снимок состояния всех операторов и позиций чтения источников. Flink делает его автоматически по интервалу и использует для восстановления после сбоя.
Барьер чекпоинта (checkpoint barrier)
Служебное событие с номером чекпоинта, которое источник вставляет в поток. Едет вместе с записями и делит поток на часть до чекпоинта и часть после.
Координатор чекпоинтов (CheckpointCoordinator)
Компонент JobManager, который запускает чекпоинты, собирает подтверждения подзадач, хранит завершённые чекпоинты и восстанавливает из них задание.
Выравнивание (alignment)
Блокировка входного канала, по которому барьер уже пришёл, до прихода барьеров по остальным каналам. Нужно для exactly-once в состоянии.
Unaligned-чекпоинт
Режим, в котором барьер обгоняет данные в сетевых буферах, а обогнанные буферы сохраняются в чекпоинт. Чекпоинты при backpressure становятся быстрее, зато больше по объёму.
Алгоритм Chandy-Lamport
Классический алгоритм распределённого снимка через маркеры в каналах. Подход Flink основан на нём и приспособлен к потоковым графам.
Exactly-once
Гарантия, что каждая запись отразится в состоянии ровно один раз даже при сбоях. Для внешних систем требует отдельной поддержки в приёмнике.
At-least-once
Гарантия, что ни одна запись не потеряется, но после сбоя часть записей может быть учтена повторно.
State backend
Способ хранения рабочего состояния и снятия снимка. Во Flink 2.2 это hashmap, rocksdb и экспериментальный forst.
RocksDB
Встраиваемое хранилище ключ-значение на диске. Flink кладёт его внутрь TaskManager и хранит там состояние в сериализованном виде.
ForSt
Ответвление RocksDB для Flink, которое хранит файлы состояния на удалённой файловой системе. Во Flink 2.2 экспериментальное.
SST-файл (Sorted String Table)
Неизменяемый отсортированный файл данных RocksDB. Неизменяемость позволяет выгружать в чекпоинт только новые файлы.
Инкрементальный чекпоинт
Чекпоинт, который выгружает только файлы, появившиеся после прошлого подтверждённого чекпоинта, и ссылается на уже выгруженные.
Файл _metadata
Файл в папке chk-N, который пишет JobManager. Содержит состояния операторов по uid и ссылки на файлы с данными.
Стратегия перезапуска (restart strategy)
Правило, по которому Flink решает, перезапускать ли задание после сбоя и через какую паузу.
Exponential-delay
Стратегия перезапуска, у которой пауза растёт в заданное число раз с каждой попыткой до верхнего предела и сбрасывается после долгой работы без сбоев.
Jitter
Случайный сдвиг паузы перезапуска. Не даёт многим заданиям после общей аварии перезапускаться одновременно.
Смещение (offset)
Номер записи в партиции Kafka. Источник Flink хранит смещения в чекпоинте и после восстановления продолжает с них.
Группа потребителей (consumer group)
Имя, под которым Kafka запоминает закоммиченные смещения читателя. Flink коммитит в неё смещения после завершения чекпоинта для мониторинга.
Backpressure
Состояние, когда нижняя вершина не успевает и верхние ждут свободных буферов. Замедляет и выровненные чекпоинты.
Savepoint
Снимок, который делают вручную для обновления или переноса задания. Всегда выровненный. Подробно в уроке 13.
checkpointLocation в Spark
Каталог Spark Structured Streaming с журналом смещений, журналом коммитов и версиями хранилища состояния по каждой порции.
