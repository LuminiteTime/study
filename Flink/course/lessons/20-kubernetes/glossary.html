Глоссарий урока

Kubernetes
Система, которая запускает контейнеры на кластере машин, следит за их числом и перезапускает погибшие.
Под (pod)
Наименьшая единица запуска в Kubernetes. Один или несколько контейнеров с общей сетью и томами. У нас каждый JobManager и TaskManager живёт в своём поде.
minikube
Учебный кластер Kubernetes из одного узла на твоей машине. С драйвером docker узел работает контейнером Docker.
kubectl
Командный клиент API Kubernetes. Создаёт, читает, меняет и удаляет объекты кластера.
Helm
Менеджер пакетов для Kubernetes. Пакет называется чартом и содержит шаблоны манифестов с настройками.
Flink Kubernetes Operator
Приложение в Kubernetes, которое следит за ресурсами FlinkDeployment и приводит кластеры Flink к описанию в них. В других уроках словом «оператор» называют шаг задания, здесь речь о контроллере.
CRD (custom resource definition)
Описание собственного типа объектов Kubernetes. После регистрации с ресурсами этого типа работают через kubectl, как с подами.
FlinkDeployment
Ресурс оператора, который описывает кластер Flink и, в режиме Application, задание в нём.
FlinkSessionJob
Ресурс оператора для задания, которое отправляется в уже работающий кластер Session.
FlinkStateSnapshot
Ресурс оператора для одного savepoint или чекпоинта. Хранит состояние операции и путь к файлам.
Reconcile
Проход контроллера, который сравнивает желаемое состояние из spec с фактическим и выполняет действия, сводящие разницу к нулю.
spec и status
Две части объекта Kubernetes. В spec пользователь пишет, что хочет, в status контроллер пишет, что получилось.
lifecycleState
Поле статуса FlinkDeployment, сводная стадия ресурса. Например UPGRADING во время апгрейда и STABLE после успешного запуска.
upgradeMode
Поле spec.job, которое задаёт, как оператор переносит состояние при апгрейде. Значения stateless, last-state и savepoint, по умолчанию stateless.
Savepoint
Снимок состояния задания, который снимают по команде для обновления или переноса. Подробно в уроке 13.
Чекпоинт (checkpoint)
Снимок состояния, который Flink делает сам по расписанию для восстановления после сбоя. Подробно в уроке 11.
HA (high availability)
Сервисы высокой доступности Flink. Хранят сведения о заданиях и чекпоинтах вне JobManager, чтобы новый JobManager продолжил работу предыдущего.
Выбор лидера (leader election)
Механизм, по которому из нескольких JobManager активным становится один. В Kubernetes HA замком служит ConfigMap кластера.
ConfigMap
Объект Kubernetes для небольших данных конфигурации, до мегабайта. Flink HA хранит в нём указатели на метаданные.
Secret
Объект Kubernetes для паролей и ключей. Под получает значение через переменную окружения или файл, и в манифест оно не попадает.
PersistentVolumeClaim (PVC)
Заявка пода на постоянный диск. Данные на нём переживают рестарт и пересоздание пода.
ReadWriteOnce
Режим доступа к тому, при котором его монтируют на запись поды только одного узла.
Deployment
Объект Kubernetes, который держит заданное число одинаковых подов и пересоздаёт погибшие. Стратегия Recreate сначала гасит старый под, потом поднимает новый.
Service
Объект Kubernetes с постоянным именем и адресом для группы подов. Через него к подам обращаются по имени в DNS кластера.
port-forward
Команда kubectl, которая пробрасывает локальный порт в конкретный под. Завершается, если под исчез.
podTemplate
Шаблон пода в FlinkDeployment. Оператор накладывает на него свои настройки и создаёт по нему поды JobManager и TaskManager.
Webhook и cert-manager
Webhook проверяет ресурсы при kubectl apply. Ему нужен TLS-сертификат, который выпускает cert-manager. В стенде webhook отключён.
Режим Application
Развёртывание, при котором кластер Flink создаётся под одно задание, а main выполняется в JobManager. Подробно в уроке 2.
Режим Session
Развёртывание, при котором кластер работает независимо от заданий и принимает их от клиентов.
Native и standalone
Способы запуска Flink в Kubernetes. В native поды TaskManager просит сам Flink, в standalone их создаёт оператор.
JobManager
Процесс, который управляет заданием и координирует чекпоинты. Здесь он же выполняет main задания.
TaskManager
Рабочий процесс Flink со слотами, в которых выполняются подзадачи.
ResourceManager
Компонент JobManager, который ведёт учёт слотов. В Kubernetes он сам заказывает поды TaskManager.
jobId
Идентификатор задания из 32 шестнадцатеричных знаков. Оператор фиксирует его в конфигурации, по нему HA находит чекпоинты.
__transaction_state
Внутренний топик Kafka, где брокер хранит состояние транзакций и связь transactional.id с producerId.
Apache Kafka
Распределённый журнал сообщений. Источник платежей и приёмник алертов PayGuard.
spark-operator
Оператор Kubernetes для Spark. Описывает приложение ресурсом SparkApplication и запускает под драйвера.
Автоскейлер (autoscaler)
Модуль оператора, который сам меняет параллелизм вершин задания по метрикам загрузки.
