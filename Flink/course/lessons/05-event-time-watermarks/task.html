Задание. Проба опозданий

Допуск 10 секунд мы выбрали наугад. Напиши оператор, который измеряет опоздания на живом потоке, чтобы выбирать допуск по данным.

  1. Класс dev.study.payguard.pipeline.LatenessProbe принимает PaymentEvent и отдаёт его же без изменений, все события, включая поздние.
  2. Событие считается поздним, если его eventTimeMs не больше текущего watermark оператора.
  3. Метрика-счётчик lateEvents считает поздние события.
  4. Метрика-гистограмма behindWatermarkMs получает для каждого позднего события, на сколько миллисекунд оно старше watermark. Храни последние 10 000 значений.
  5. В задании проба стоит сразу после split-parsed, имя и uid у неё lateness-probe. Подсчёт сумм продавцов читает её выход.
  6. Тест на тестовом стенде проверяет, что позднее событие не потерялось.

Готово, если ./gradlew test зелёный, задание работает на стенде, а в метриках подзадач вершины с источником есть lateEvents и перцентили behindWatermarkMs.

Подсказки. Обычной ProcessFunction без ключа таймеры недоступны, но узнать текущий watermark через контекст можно. Готовая реализация гистограммы есть в пакете org.apache.flink.runtime.metrics, модуль flink-runtime приходит вместе с flink-streaming-java. Тестовый стенд умеет подавать не только записи, но и watermark. Проба окажется в одной цепочке с источником, ищи её метрики по имени оператора.
