Глоссарий урока

Постмортем (postmortem)
Документ о разборе аварии. В нём хронология, влияние, корневая причина, усилившие факторы и действия, чтобы авария не повторилась. Виноватых в нём не ищут.
Runbook
Инструкция для дежурного. На каждый алерт в ней записано, что проверить первым, как отличить причины и что делать.
Хаос-тестирование (chaos testing)
Плановые отказы компонентов на работающей системе с проверкой, что гарантии сохраняются и система восстанавливается сама.
InvalidPidMappingException
Ошибка брокера Kafka. Продюсер прислал producerId, который не связан с его transactional.id. В клиенте 4.2.0 наследует ApplicationRecoverableException и требует пересоздать продюсера.
__transaction_state
Служебный топик Kafka, где координатор транзакций хранит связи transactional.id с producerId, эпохой и состоянием транзакций.
Координатор транзакций (transaction coordinator)
Роль брокера Kafka, которая выдаёт продюсерам producerId и эпоху, ведёт их транзакции и фиксирует или отменяет их.
producerId и эпоха (epoch)
Номер продюсера и счётчик его поколений. По паре брокер отличает живого продюсера от устаревшего и не даёт старому зафиксировать транзакцию.
transactional.id
Постоянное имя транзакционного продюсера Kafka. Приёмник Flink строит его из префикса, номера подзадачи и номера чекпоинта.
Committable
Объект, который Writer приёмника передаёт Committer на чекпоинте. У Kafka в нём имя транзакции, producerId и эпоха. Хранится в состоянии, пока транзакция не зафиксирована.
Committer
Оператор приёмника Sink V2, который фиксирует подготовленные транзакции после завершения чекпоинта. Его uid строится как Sink Committer плюс uid приёмника.
Exponential-delay
Стратегия перезапуска Flink, при которой пауза между попытками растёт до предела. По умолчанию число попыток не ограничено.
allowNonRestoredState
Разрешение запустить задание из снимка, в котором есть состояние без подходящего оператора. Такое состояние отбрасывается.
uid оператора
Постоянный идентификатор оператора, по которому Flink находит его состояние в savepoint и чекпоинте.
Savepoint
Снимок состояния задания, который делают по команде, например перед апгрейдом. Из него запускают новую версию задания.
Exactly-once
Гарантия, что каждая запись отражается в результате ровно один раз, даже при сбоях. В Kafka держится на транзакциях и read_committed.
read_committed
Уровень изоляции потребителя Kafka, при котором он видит только данные зафиксированных транзакций. read_uncommitted видит и отменённые.
PersistentVolumeClaim (PVC)
Заявка пода Kubernetes на постоянный том. Данные на нём переживают перезапуск и пересоздание контейнера.
ConfigMap
Объект Kubernetes с данными в виде ключей и значений. Flink HA хранит в нём лидера и указатель на последний чекпоинт.
FlinkDeployment
Ресурс оператора Flink в Kubernetes, описывающий кластер и задание. Оператор приводит кластер к его спецификации.
SASL
Simple Authentication and Security Layer. Способ аутентификации в протоколе Kafka, клиент представляется до первых запросов.
PLAIN
Механизм SASL, который передаёт логин и пароль как есть. Без TLS пароль виден в сети.
TLS, SASL_SSL и SASL_PLAINTEXT
TLS шифрует соединение. SASL_SSL это аутентификация SASL поверх TLS, вариант для прода. SASL_PLAINTEXT это аутентификация без шифрования, вариант учебного стенда.
JAAS
Java Authentication and Authorization Service. Стандартный механизм Java, клиент Kafka читает из строки JAAS модуль входа, логин и пароль.
Надстройка Compose (override file)
Дополнительный файл Compose, который сливается с основным. Переменная COMPOSE_FILE перечисляет файлы через двоеточие.
GitHub Actions
Система CI в GitHub. Сценарии лежат в .github/workflows и запускаются по событиям репозитория, например push или тегу.
GitHub Container Registry (ghcr.io)
Реестр образов контейнеров при GitHub. Сценарий публикует туда образ встроенным токеном GITHUB_TOKEN.
Аннотации стабильности
Метки Public, PublicEvolving и Experimental на классах Flink. По ним видно, какую совместимость Flink обещает между версиями. PublicEvolving между минорными версиями не обещает ничего.
Release notes
Заметки к выпуску. Список изменений версии, которые могут задеть работающие задания.
Теневая копия (shadow copy)
Способ обновления, при котором новый кластер поднимают рядом со старым, запускают задание из savepoint и гасят старый после проверки.
Production readiness checklist
Список проверок перед первым запуском задания в проде. У Flink есть свой в документации.
Apache Kafka
Распределённый журнал сообщений. Записи хранятся в топиках и читаются повторно.
