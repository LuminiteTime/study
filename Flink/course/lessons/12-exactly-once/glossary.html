Глоссарий урока

At-least-once
Гарантия, при которой ни одна запись не теряется, но после сбоя часть записей может прийти повторно.
Exactly-once
Гарантия, при которой каждое событие влияет на результат ровно один раз. Для состояния Flink её дают чекпоинты, для внешней системы нужен транзакционный или идемпотентный приёмник.
End-to-end exactly-once
Exactly-once от источника до внешнего приёмника. Требует воспроизводимого источника и транзакционного или идемпотентного приёмника.
Двухфазная фиксация (two-phase commit)
Протокол из подготовки и фиксации. Во Flink подготовка идёт на барьере чекпоинта, фиксация после его завершения.
Предкоммит (pre-commit)
Первая фаза. Writer сбрасывает буферы, помечает транзакцию подготовленной и передаёт её описание в Committer.
SinkWriter
Оператор приёмника, который пишет записи во внешнюю систему. В транзакционном режиме пишет так, чтобы данные ещё не были видны.
Committer
Оператор приёмника, который делает подготовленные данные видимыми после завершения чекпоинта. Повторная фиксация не должна ничего менять.
Committable
Описание подготовленных данных, которое Writer передаёт Committer. У Kafka это имя транзакции, producerId и эпоха.
notifyCheckpointComplete
Вызов, который оператор получает после того, как JobManager объявил чекпоинт завершённым. По нему Committer фиксирует транзакции.
Транзакция Kafka
Группа записей одного продюсера, которая становится видна потребителям read_committed целиком после фиксации или не становится видна вовсе.
transactional.id
Имя транзакционного продюсера в Kafka. Flink собирает его из префикса, номера подзадачи и номера чекпоинта.
producerId и эпоха
Числа, по которым брокер узнаёт продюсера. Новый продюсер с тем же transactional.id получает новую эпоху, и старый больше не может фиксировать.
Fencing
Вытеснение старого продюсера новым с тем же transactional.id. Попытка старого продолжить заканчивается ProducerFencedException.
isolation.level
Настройка потребителя Kafka. read_uncommitted, значение по умолчанию, отдаёт всё, включая прерванные транзакции. read_committed отдаёт только зафиксированные.
LSO (last stable offset)
Смещение перед первой открытой транзакцией в партиции. Потребитель read_committed не читает дальше него.
transaction.timeout.ms
Настройка продюсера Kafka. Через это время брокер сам прерывает незафиксированную транзакцию. Приёмник Flink по умолчанию ставит час.
transaction.max.timeout.ms
Настройка брокера Kafka, предел для transaction.timeout.ms. По умолчанию 15 минут.
__transaction_state
Внутренний топик Kafka, где брокер хранит состояние транзакций. Без постоянного тома теряется при перезапуске брокера.
InvalidPidMappingException
Ошибка Kafka, когда producerId не связан с transactional.id на брокере. У нас возникла после потери журнала транзакций.
Идемпотентность
Свойство операции, при котором повторное выполнение даёт тот же результат, что и однократное.
Upsert
Вставка, которая при существующем ключе обновляет строку. В PostgreSQL пишется как INSERT ... ON CONFLICT DO UPDATE.
Детерминированный идентификатор
Идентификатор, который вычисляется из содержимого записи и совпадает при повторной обработке. У нас alertId из правила и платежа.
XA-транзакция
Стандарт распределённых транзакций для баз данных. JDBC-приёмник Flink использует его в режиме exactly-once.
JDBC
Стандартный интерфейс Java для работы с реляционными базами. Коннектор Flink для него выходит отдельно, как и коннектор Kafka.
PostgreSQL
Реляционная база данных. В проекте хранит справочник продавцов и итоги по окнам.
