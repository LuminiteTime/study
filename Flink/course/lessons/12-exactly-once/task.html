Задание. Итоги продавцов в PostgreSQL

Минутные итоги по продавцам сейчас уходят в топик merchant.stats в режиме at-least-once. После каждого падения там появляются повторы. Отчётам нужна таблица, в которой у каждого продавца одна строка на окно. Перенеси итоги в PostgreSQL и сделай запись идемпотентной.

  1. Добавь в build.gradle.kts JDBC-коннектор Flink версии 4.1.0-2.2, модули flink-connector-jdbc-core и flink-connector-jdbc-postgres. Драйвер PostgreSQL в проекте уже есть.
  2. Опиши в sql/init.sql таблицу merchant_stats с колонками продавца, начала и конца окна, числа платежей, суммы и времени обновления. Первичный ключ выбери так, чтобы одно окно продавца было одной строкой.
  3. Напиши класс JdbcSinks с методом merchantStats(), который возвращает приёмник для MerchantStats. Запрос вставки при конфликте ключа обновляет итоги.
  4. В PayGuardJob замени приёмник итогов на новый, назови его merchant-stats-postgres с таким же uid. Поле merchantStatsTopic из JobConfig и топик merchant.stats из kafka-init больше не нужны, убери их.

Готово, если после двух убийств TaskManager под нагрузкой в 200 платежей в секунду задание работает, в графе есть вершина с merchant-stats-postgres: Writer, а в таблице ровно по одной строке на продавца и окно для всех 50 продавцов.

Подсказки.

  • Новый строитель приёмника лежит в пакете org.apache.flink.connector.jdbc.core.datastream.sink, класс JdbcSink. Нужен вариант at-least-once, транзакции здесь не понадобятся.
  • Адрес базы, пользователь и пароль уже есть в окружении JobManager и TaskManager, переменные PAYGUARD_DB_URL, PAYGUARD_DB_USER и PAYGUARD_DB_PASSWORD.
  • Окно продавца с допуском опоздания может сработать для одного окна несколько раз. Подумай, что должно произойти со строкой при втором срабатывании.
  • Образ PostgreSQL выполняет скрипты из docker-entrypoint-initdb.d только при создании пустой базы. Чтобы новая таблица появилась, контейнер базы придётся пересоздать вместе с его томом.
