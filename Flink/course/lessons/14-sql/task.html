Задание. Выручка по уровню риска и запуск из jar

Финансы просят новый отчёт. Каждую минуту для каждого уровня риска продавца нужны три продавца с самой большой выручкой. Уровень риска лежит в таблице merchants в PostgreSQL. Плюс платформа требует, чтобы SQL проходил ту же сборку и тот же релиз, что и код, поэтому скрипт должен ехать в jar.

  1. Создай таблицу risk_revenue в sql/init.sql с полями risk_level, window_start, top_rank, merchant_id, amount_minor. Подбери первичный ключ так, чтобы повторная запись окна перезаписывала строки.
  2. Напиши src/main/resources/sql/risk_revenue.sql. Обогати платёж уровнем риска через lookup join с кэшем на 10000 строк и 5 минут. Продавец без записи в справочнике получает уровень UNKNOWN. Посчитай выручку в минутном окне TVF и оставь топ-3 через Window Top-N.
  3. Напиши класс dev.study.payguard.job.SqlJobRunner. Он получает имя скрипта аргументом --script, читает его из ресурсов jar и выполняет инструкции по очереди через TableEnvironment.
  4. Добавь нужную зависимость в build.gradle.kts так, чтобы она не попала в толстый jar.
  5. Отправь задание на SQL-кластер через flink run.

Критерии готовности такие. В Web UI на порту 8082 в плане есть вершины LookupJoin, LocalWindowAggregate, GlobalWindowAggregate и WindowRank. В таблице не больше трёх строк на уровень риска и минуту. В верхней строке уровня HIGH стоит горячий продавец m-0000.

Подсказки. Для lookup join нужен атрибут времени обработки, посмотри функцию PROCTIME() и конструкцию FOR SYSTEM_TIME AS OF. Window Top-N требует, чтобы PARTITION BY содержал и начало, и конец окна. Точка входа в толстом jar занята основным заданием, поэтому главный класс придётся указать флагом. При разборе скрипта подумай, на чём разрезать текст, чтобы инструкции и комментарии не сломали executeSql.
