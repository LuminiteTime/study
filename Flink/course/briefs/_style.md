## Разметка, которую разворачивает `course/tools/build.py`
- `<div data-code="lesson-05/src/main/java/.../X.java" data-lines="10-30"></div>`: код проекта из `solutions/`. Файл целиком без `data-lines`. Никогда не перепечатывай код проекта руками, только через этот тег, иначе он разойдётся с проверенным.
- `<div data-diff="lesson-04/build.gradle.kts lesson-05/build.gradle.kts"></div>`: что изменилось между снапшотами. Для новых файлов показывай файл целиком, для правок diff.
- `<pre data-lang="bash" data-title="терминал">команды</pre>` и `<pre data-lang="text" data-title="вывод" data-output>вывод</pre>`. Спецсимволы `<`, `>`, `&` экранируй.
- `<div class="translation-block"><div class="translation-code" data-code="..." data-lines="..."></div><div class="translation-english"><span class="translation-label">ПРОСТЫМИ СЛОВАМИ</span><div class="translation-lines"><p class="tl">...</p></div></div></div>`: разбор кода построчно. По одной `tl` на смысловой кусок.
- `<dl class="glossary"><dt data-match="чекпоинт|checkpoint">Чекпоинт (checkpoint)</dt><dd>...</dd></dl>`: глоссарий. `data-match` содержит основы слова через `|`, первое вхождение на каждой вкладке само получит подсказку. Глоссарий покрывает все термины урока, не меньше 8, включая термины других технологий (Kafka, RocksDB, Prometheus).
- Ответ: `<button class="reveal-answer">Показать ответ</button><div class="answer-body" hidden>...</div>`.
- Интерактив (квиз, чат, анимация потока, callout) пишется по `~/.claude/skills/codebase-to-course/references/interactive-elements.md`. Читай только нужные разделы. Подписи по-русски. Все `id` уникальны на весь курс, бери префикс урока (`flow-l05a-1`, `chat-l05`, `quiz-l05-1`). В JSON `data-steps` нет апострофов.
- Свои визуализации: разметка `<div class="viz" id="viz-l05"><p class="viz-title">...</p>...</div>`, код в `course/viz/05.js` (IIFE на чистом JS без библиотек). Цвета только через CSS-переменные (`var(--color-accent)` и другие), тогда работает тёмная тема. Вешай обработчики на `DOMContentLoaded`. SVG с `viewBox`, ширина подстраивается. Анимация только по кнопке.

## Блок «В исходниках» (обязательно, минимум 2 на урок)
Пользователь любит проверять, как инструмент работает, в его коде. Каждое важное утверждение про внутреннее устройство подтверждается цитатой и ссылкой на раздел документации.

```html
<div class="source-proof">
<p class="source-proof-title">В исходниках</p>
<p>Что мы проверяем и на что смотреть в этом коде.</p>
<div data-src="flink:flink-runtime/src/main/java/org/apache/flink/.../X.java" data-lines="645-660" data-must="inputProcessor.processInput"></div>
<p>Что из этого следует.</p>
<p class="doc-links">Документация: <a href="https://nightlies.apache.org/flink/flink-docs-release-2.2/docs/ops/state/checkpoints/" target="_blank" rel="noopener">Checkpoints</a></p>
</div>
```

`data-must` это строка, которая обязана быть в диапазоне. Если её нет, сборка падает. Цитируй 5–30 строк. Код не пересказывай, говори, что именно он доказывает. Подтверждай только то, что сам увидел в файле. Сомнительное формулируй как наблюдение из кода или убери.

## Содержание вкладок
- **Теория.** Начни с промышленной проблемы, потом механизм. Сравни со Spark там, где это помогает. Минимум один SVG или интерактив на урок, блоки «В исходниках», 1–2 callout, в конце квиз на сценарии (2–3 вопроса, не на память). Одна свежая метафора из быта. Рестораны и кухни запрещены, метафоры других уроков тоже.
- **Практика.** Пошагово, на каком файле что меняем и почему. Каждая новая зависимость показана рабочим кодом Gradle. Каждая команда объяснена, у каждого важного флага сказано, что он делает. Вывод и как его читать. Минимум один `translation-block`. Ошибки, на которые реально нарвались (из measurements), показывай с лечением.
- **Задание.** Конкретная задача на проект, критерии готовности, подсказки. Код решения не показывать.
- **Ответ.** Скрыт кнопкой. Полное решение через `data-code` из снапшота, объяснение решений, как проверить.
- **Глоссарий.** См. выше.

Снапшот `solutions/lesson-NN` содержит состояние после практики и задания вместе. Определи, какие файлы относятся к заданию (указано в бриф-файле урока) и покажи их только в «Ответе». В тексте «Практики» говори, что файлы решения пока создавать не нужно.

Команды запуска пиши от папки проекта. JDK: `export JAVA_HOME=$(/usr/libexec/java_home -v 17)` упомянута в уроке 1, дальше не повторяй. rtk в командах не упоминай.

## Стиль текста (проверяется `python3 course/tools/lint_prose.py`)
Текст проходит требования скилла humanizer. Запрещено:
- Двоеточие в прозе. Перефразируй на точку или запятую. В коде, `<code>` и атрибутах можно. В заголовках и таблицах тоже нельзя.
- Тире как разделитель («—», « – », « -- »). Перефразируй. Диапазоны чисел пиши дефисом без пробелов.
- Конструкции «не X, а Y» и «не просто». Скажи прямо, что есть. Сравнивая со Spark, пиши две отдельные фразы про каждую систему.
- Заключительные сентенции, которые повторяют абзац.
- Штампы: ключевой, стоит отметить, важно отметить, давайте, погрузимся, по сути, на самом деле, таким образом, играет роль, в современном мире.
- Натянутые тройки, эмодзи-украшения, жирные метки в начале пунктов.
- Выдуманные обозначения. Каждый термин Flink и других систем объяснён при первом упоминании и есть в глоссарии.

После записи файла запусти `npm run check` из `course/` и исправь все замечания по своему уроку. Замечания других файлов не трогай. В конце верни одну строку на каждый урок: файл, число цитат исходников, что не удалось подтвердить. Других файлов проекта (solutions, чужие уроки, `scripts/`, `styles/`, `tools/`) не меняй.
